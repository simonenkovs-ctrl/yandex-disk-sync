# История изменений

## [1.2.1] — 2026-11-05

### Исправлено
- Файл удалялся с ПК при первом запуске, если его ещё не было в облаке (CASE 2 в sync_engine.py) — теперь файл всегда загружается, а не удаляется
- Синхронизация зацикливалась независимо от интервала (check_connection_async вызывал trigger_sync) — убран лишний триггер
- Манифест `.sync_manifest.json` не обновлялся после загрузки/скачивания, что приводило к повторной загрузке тех же файлов — теперь манифест дополняется newly synced файлами в конце каждого цикла

## [1.2.0] — 2026-11-04

### Добавлено
- Манифест v2: поля `version` и `timestamp`, TTL (по умолчанию 3600 с, ключ `manifest_ttl_seconds`).
- Расширенный список исключений: `.bak`, `.backup`, `.old`, `.temp`, `.partial`, `.download`, `.swo` — и для локальных, и для удалённых файлов.
- Поддержка заголовка `Retry-After` при ответах 429/5xx.

### Исправлено
- `NameError: skipped_files` в `_do_download` — любая ошибка скачивания прерывала весь цикл синхронизации.
- Колбэк `on_sync_completed` «съедался» блоком отчёта о пропущенных файлах после маркерного патча; guard восстановлен.
- Двойной retry в `list_folder_recursive` (3×3 = 9 попыток); оставлен один уровень — в `_request`.
- Чекбокс автозапуска читал значение из конфига, а не из реестра; команда в dev-режиме была голым путём к `.py`.
- Ответ 404 при скачивании вызывал полный rebuild манифеста; теперь удаляется только устаревшая запись.

### Изменено
- `_is_ignored()` — единый фильтр для `local_files` и `remote_files`.
- Запись манифеста атомарна (tmp-файл + upload); `version: 2` включает семантику TTL.
